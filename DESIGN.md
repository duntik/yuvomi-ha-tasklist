# Yuvomi Tasklist: реализация и следующие шаги

Репозиторий: https://github.com/duntik/yuvomi-ha-tasklist

## Что создано

Прототип `0.1.0` находится в `integration/`. Это custom integration `yuvomi`
для Home Assistant, устанавливаемая через HACS как пользовательский репозиторий.
Она создаёт стандартную сущность `todo.*`, читает задачи Yuvomi и отправляет
изменения через REST API. Yuvomi остаётся источником данных.

Для простой установки выбран вариант без собственной сборки HA: интеграция
автоматически загружает небольшой frontend-модуль. Он перехватывает открытие
редактора только для списка Yuvomi и показывает расширенный диалог в обычном
сценарии стандартного To-do. В стандартном разделе добавляется кнопка фильтров
и архива. Отдельная карточка, панель или контейнер не нужны.

Это экспериментальное расширение интерфейса: модель `TodoItem` и исходники
встроенного HA не изменяются. Оно зависит от события редактора и структуры
стандартной панели. При изменениях HA может потребоваться обновление модуля.
Расширение отключается в настройках интеграции; базовый `todo` продолжает работать.

## Возможности прототипа

- Базовое чтение, создание, переименование, описание, срок, завершение,
  повторное открытие и удаление через стандартную платформу `todo`.
- В расширенном редакторе: три статуса, приоритет, категория, исполнители,
  дата начала, теги, повторения, баллы, видимость и блокировка параметров.
- Добавление, завершение и редактирование подзадач.
- Архивирование, восстановление, поиск и фильтры категории/статуса.
- Обновление стандартного списка раз в 30 секунд и после операций записи.
- Настройка через UI, повторная авторизация, русский и английский интерфейсы.

Не реализованы комментарии, вложения, история завершений, напоминания и отчёты
по наградам. Полный паритет модуля Tasks Yuvomi пока не достигнут.
Покупки не входят в выбранный пользователем охват.

## Backend

- `api.py`: Bearer token, таймауты, отказ от HTTP redirects, проверка ответов.
- `config_flow.py`: адрес, токен, часовой пояс семьи Yuvomi, опция frontend.
- `coordinator.py`: общее обновление и сериализация операций записи.
- `todo.py`: адаптер стандартного HA To-do без сброса статуса `in_progress`.
- `websocket.py`: расширенные операции с проверкой прав HA на сущность.
- `frontend/yuvomi.js`: диалог и подключение к стандартному интерфейсу.

Токен хранится в HA и не отправляется браузеру. Браузер использует HA WebSocket.
Доступные пользователю HA задачи определяются правами на сущность и правами
пользователя токена Yuvomi. Индивидуальные аккаунты HA не сопоставляются с
аккаунтами Yuvomi.

## API Yuvomi

- `GET /api/v1/tasks?include_future=1`
- `GET /api/v1/tasks/meta/options`
- `GET /api/v1/tasks/:id`
- `POST /api/v1/tasks`
- `PUT /api/v1/tasks/:id`
- `PATCH /api/v1/tasks/:id/status`
- `PATCH /api/v1/tasks/:id/archive`
- `DELETE /api/v1/tasks/:id`

Для токена требуется `tasks:write`, включающий чтение. Для завершения стандартной
задачи используется endpoint status; повторы, историю и награды рассчитывает
сервер Yuvomi. После записи задачи перечитываются. Расширенный редактор отправляет
только изменённые поля, сохраняя остальные настройки задачи. Одновременное
изменение одного поля не имеет автоматического разрешения конфликтов.

## Проверки и выпуск

Локально проверены HTTP-клиент, обработка ошибок и redirects, частичные обновления,
безопасное отображение текста и перехват редактора только для сущностей Yuvomi.
CI запускает тесты адаптера и проверки прав с библиотеками HA 2026.9.4 на Linux,
а также проверку упаковки HACS. Реальная пользовательская установка ещё не проверена.

Инструкции установки и текущие ограничения: `integration/README.md`.
Для проверки на серверах пользователя нужны версии и доступные адреса HA/Yuvomi.
API-токен следует вводить в UI интеграции, а не публиковать в репозитории или чате.

## Полное расширение самого HA

Если потребуется расширение официальной модели To-do для всех провайдеров,
нужны отдельные изменения Home Assistant Core и Frontend с дополнительными
полями и feature flags. Обычная HACS-интеграция их не устанавливает. Это отдельное
направление; принятие изменений официальным проектом не гарантируется.
